HIGH F-003 · Privilege escalation: PassRole to new Lambda function — test-passrole
RulePRIV-015 · Privilege Escalation · exploitability: latent · MITRE T1648, T1098
Policyci-deploy (inline)
Sid / Effect(none) / Allow
Offending actionsiam:PassRole, lambda:CreateFunction, (missing) lambda:InvokeFunction
Resource*
RiskCan create a Lambda function that executes attacker code with any passable execution role. Required permissions present: iam:PassRole, lambda:CreateFunction.
Attack path1) test-passrole calls lambda:CreateFunction with --role pointing at a privileged role/policy (allowed by iam:PassRole on that ARN). 2) The function code reads AWS_ACCESS_KEY_ID/SECRET/SESSION_TOKEN from its environment or calls IAM directly. 3) Once invoked, the attacker operates with the execution role's privileges.
RecommendationScope iam:PassRole to the exact execution role ARN(s) and add Condition StringEquals iam:PassedToService = lambda.amazonaws.com; scope the compute action to a function/instance naming prefix.
• No role in this export currently trusts lambda.amazonaws.com; PassRole on "*" means the escalation becomes immediate the moment any privileged role trusting lambda.amazonaws.com exists (common for Lambda/EC2 execution roles).
• No trigger permission (lambda:InvokeFunction / lambda:CreateEventSourceMapping / lambda:CreateFunctionUrlConfig / lambda:AddPermission) found - the chain is one permission away from executable, or relies on an existing event source / another principal to invoke it.
